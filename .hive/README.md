## Prepare a checkout

Install the matching Hive toolchain (this contract was generated by Beeswax/Scent 0.9.1) and the Hive-compatible `br` build. Read `beeswax setup --help` for first initialization and `beeswax sync --help` for an existing contract.

```sh
pnpm install --frozen-lockfile
beeswax sync
beeswax setup --tracker adopt --environment mise --yes
beeswax beads env --json
mise exec -- br where --json
mise exec -- bee kinds --all
mise exec -- busybee input-schema do-work --json
```

Adopt requires an already selected tracker; follow the setup CLI's init/bootstrap guidance for a first checkout. It writes ignored `mise.local.toml`, not machine paths into the committed contract. Trust the local Mise configuration and activate Mise in your shell, or prefix direct native commands with `mise exec --`. Launch direct Pi with `mise exec -- pi`: without `BEADS_DB`, native Beads can silently discover an unrelated home-directory tracker. Managed bees inherit their explicitly selected database.

Complete each harness's trust steps: Pi requires project trust; Codex requires project trust and `/hooks` review. Claude gets generated hooks through `.claude/settings.json`. Generated adapters do not prove runtime delivery.

The initial local tracker is `.worktrees/tracker--state/.beads/beads.db` on branch `tracker/state`. Keep that permanent checkout. `beeswax beads env --json` is authoritative for selection; preserve an explicitly supplied `BEADS_DB`. A new clone cannot bootstrap this first tracker until its branch is published. Follow `beeswax skills file repository-setup references/publication.md` only at an authorized publication checkpoint.

Run `bee setup --beads-db DATABASE --actor ACTOR --json` once per selected database to install the local attention query. Verify `bv --robot-recipes` in both the application and permanent tracker checkout; Beeswax owns only the `_hive_` views.
