# Codex 0.156.1 session schema

Verified on local rollouts stamped `cli_version: "0.156.1"` on 2026-09-27.
The covered message/tool fields also match local desktop-app rollouts stamped
`0.155.0-alpha.16.4`; this is not a claim about every internal protocol field.
Use `DLG` for the stable dialogue log and `RAW` for the selected raw rollout.
The stable log schema is owned by this repo, independently of Codex versions.

## Ground rules

- Never modify dialogue logs or raw session files.
- The dialogue log is append-only JSONL: one JSON object per line.
- `event` is one of `session_start`, `prompt`, `reply`, or `file`.
- `prompt` records contain the submitted user text in `.text`.
- `reply` records contain final assistant text in `.text` only when Codex
  includes final assistant text in the `Stop` hook payload.
- `file` records are emitted from `PostToolUse`; shell commands have `.command`
  and usually `file_path: null`.
- There is no Codex `SessionEnd` hook in the current capture script.
- Raw rollout files are Codex-internal protocol logs; their schema can drift.

## Conversation extraction

```bash
# User prompts only.
jq -r 'select(.event=="prompt") | "## prompt (\(.ts))\n\(.text)\n"' "$DLG"

# Assistant final replies only.
jq -r 'select(.event=="reply") | "## reply (\(.ts))\n\(.text)\n"' "$DLG"

# Q&A transcript. If several reply records exist for one prompt_id, keep the last.
jq -sr 'map(select(.agent_id==null)) |
  (map(select(.event=="reply")) | group_by(.prompt_id) | map(.[-1])) as $replies |
  (map(select(.event=="prompt")) + $replies) | sort_by(.ts) |
  .[] | "## \(.event) (\(.ts))\n\(.text)\n"' "$DLG"

# Chronological compact transcript.
jq -r 'select(.event=="prompt" or .event=="reply") |
  "[\(.event)] \(.text[:200])"' "$DLG"
```

An interrupted turn can have a `prompt` with no matching `reply`; this is
expected because `Stop` may not fire on interrupt.

## Tool and file activity

```bash
# Tool/file event counts.
jq -r 'select(.event=="file") | .tool // "unknown"' "$DLG" |
  sort | uniq -c | sort -rn

# Shell commands captured from tool events.
jq -r 'select(.event=="file" and .command != null) |
  "\(.ts)\t\(.command)"' "$DLG"

# Files read or touched when the hook payload includes a path.
jq -r 'select(.event=="file" and .file_path != null) |
  "\(.tool)\t\(.file_path)"' "$DLG" | sort -u

# Events grouped by prompt id for one turn.
PID=<prompt-id>
jq -r --arg pid "$PID" 'select(.prompt_id==$pid) |
  if .event=="file" then "[file] \(.tool) \(.file_path // .command // "")"
  else "[\(.event)] \(.text // "")"
  end' "$DLG"
```

## Raw Codex rollout schema

Each JSONL record has `timestamp`, `type`, and `payload`. The first
`session_meta` payload includes `cli_version`, `session_id`, `id`, `cwd`,
`originator`, `source`, `thread_source`, `model_provider`, and optional `git`.

| Record                                                              | Fields used for introspection                                                                                                                                      |
| ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `response_item`, payload `type: "message"`                          | `role`, `content[]`, `phase`; text blocks have `type: "input_text"` or `"output_text"` and `text`                                                                  |
| `response_item`, `function_call`                                    | `call_id`, `name`, `arguments` (JSON string)                                                                                                                       |
| `response_item`, `custom_tool_call`                                 | `call_id`, `name`, `input` (freeform string)                                                                                                                       |
| `response_item`, `function_call_output` / `custom_tool_call_output` | `call_id`, `output`; join to requests by `call_id`                                                                                                                 |
| `response_item`, `web_search_call`                                  | `id`, `action`, `status`                                                                                                                                           |
| `response_item`, `reasoning`                                        | `summary`, possibly `encrypted_content`; not visible assistant prose                                                                                               |
| `event_msg`                                                         | Lifecycle events including `task_started`, `task_complete`, `turn_aborted`; `item_completed` wraps completed items; `token_count` carries `info` and `rate_limits` |
| `turn_context`                                                      | `turn_id`, `cwd`, `model`, `effort`, permission and collaboration settings                                                                                         |
| `token_usage_record`                                                | `session_id`, `thread_id`, `turn_id`, `root_turn_id`, `usage`, `thread_token_usage`, `turn_token_usage`                                                            |
| `world_state`                                                       | `full`, `state`; environment snapshots                                                                                                                             |

Use `response_item` messages for raw dialogue. These versions do not use the old
`event_msg.user_message` / `event_msg.agent_message` recipes. Do not combine
message records with `item_completed` copies when counting messages. User-role
records can contain injected context as well as typed input; prefer the stable
log when the distinction matters. Assistant `phase` distinguishes commentary
from final replies when present. A message record is not necessarily a whole turn.

```bash
# Basic raw session summary.
jq -sr '{
  session_id: (map(select(.type=="session_meta"))[0].payload.session_id),
  version: (map(select(.type=="session_meta"))[0].payload.cli_version),
  cwd: (map(select(.type=="session_meta"))[0].payload.cwd),
  entries: length,
  user_messages: [.[] | select(.type=="response_item" and .payload.type=="message" and .payload.role=="user")] | length,
  assistant_messages: [.[] | select(.type=="response_item" and .payload.type=="message" and .payload.role=="assistant")] | length
}' "$RAW"

# Raw user and assistant text in file order (includes commentary).
jq -r 'select(.type=="response_item" and .payload.type=="message") |
  select(.payload.role=="user" or .payload.role=="assistant") |
  "[\(.payload.role)] " + ([.payload.content[] |
    select(.type=="input_text" or .type=="output_text") | .text] | join("\n"))' "$RAW"

# Final assistant text only.
jq -r 'select(.type=="response_item" and .payload.type=="message" and
  .payload.role=="assistant" and .payload.phase=="final") |
  .payload.content[] | select(.type=="output_text") | .text' "$RAW"

# Both structured and freeform tool requests.
jq -c 'select(.type=="response_item") | .payload |
  select(.type=="function_call" or .type=="custom_tool_call") |
  {call_id, name, arguments, input}' "$RAW"

# Matching tool result.
TID=<call-id>
jq -c --arg id "$TID" 'select(.type=="response_item") | .payload |
  select((.type=="function_call_output" or .type=="custom_tool_call_output") and .call_id==$id) |
  .output' "$RAW"
```

Inspect record types and representative shapes before extending these recipes;
this reference covers useful observed fields, not the entire internal protocol.
