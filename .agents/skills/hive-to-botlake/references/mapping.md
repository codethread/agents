# Hive/Beads mapping

| Source                                                | Botlake Work                                             | Review boundary                                                                                                                              |
| ----------------------------------------------------- | -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Epic/feature or issue containing work                 | Group                                                    | Only groups can be parents. Preserve original type; review any container's own executable scope.                                             |
| Task/bug/chore or other executable leaf               | Task                                                     | Preserve source type in metadata; unknown types require review.                                                                              |
| Title, description, design and notes                  | Full brief plus historical notes                         | Keep source prose; preserve source-qualified ID, external references, labels, owners, timestamps and close reasons.                          |
| Child `depends_on_id=PARENT`, type `parent-child`     | Child's `--parent PARENT_GROUP`                          | Reverse Beads dependency direction into parent → child containment.                                                                          |
| Dependent `depends_on_id=PREREQUISITE`, type `blocks` | `work link DEPENDENT PREREQUISITE --relation depends-on` | Same direction. Review unsupported relationship types; never turn contextual links into blockers.                                            |
| Priority 0…4                                          | P0…P4                                                    | Preserve the scale; reject missing/unknown values for review rather than promoting urgency.                                                  |
| Open/in_progress                                      | Open, initially HITL and unassigned                      | Agent claims are historical. Enable AFK only after verification and review of remaining holds.                                               |
| Draft/blocked/deferred, HITL or review/release hold   | Open HITL on affected tasks                              | Preserve blocker/defer date and required decision; Work has no equivalent draft/blocked/defer status. Preserve any actual prerequisites too. |
| Closed                                                | Closed where containment permits                         | Preserve close reason/outcome, including abandonment; closure does not mean success.                                                         |
| Acceptance text                                       | Task criteria or group brief                             | Do not invent successful resolutions. Criteria must be explicitly assessed before task closure.                                              |
| Assignee/owner, comments and history                  | Historical attribution and selected decisions            | New assignments require authorization; old agent names do not establish current custody.                                                     |
| `system` beads, Bee requests, Busy Bee runs/gates     | Excluded runtime evidence                                | Import authored work context only, not automation state. Record counts and exclusions.                                                       |

A blocked issue without a representable prerequisite stays HITL with its blocker recorded. A group-level hold does not automatically hold its descendant tasks. Review excluded/cross-repository prerequisites explicitly; use cross-lake Work links only when their owner lake and endpoint have been verified.

No source IDs, lifecycle timestamps, JSONL snapshots, claims, workflow transitions or tracker Git history are transplanted into Botlake internals. Preserve raw capture evidence and map returned destination IDs in the journal.
